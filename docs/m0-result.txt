VERDICT: the gate in PRD §0.2 clears.

  Threshold        >= 5 collisions in 30 days
  Measured         97 (of 108 raw, restricted to sessions whose lifetimes
                   genuinely overlap), across 8 distinct days

Caveat worth carrying into M1: the 97 are CLUSTERED into 8 days, not spread
evenly. Collisions are rare on a normal day and common on a parallel one --
which is the behaviour the thesis predicted, but it means "collisions per day"
is the wrong headline metric.  "Collisions per day of parallel work" is the
real one.

Method notes -- what counts, and what was excluded:
  - subagent (isSidechain) records are attributed to the parent session, so a
    session colliding with its own subagent is not counted
  - noise dropped: node_modules, .git, dist/build/coverage, *.log, *.lock,
    /tmp and /private/tmp scratch
  - one row per (file, session-pair); repeated edits inside one overlap are a
    single event
  - "genuinely overlapping" requires the two sessions' active spans to
    intersect, not merely two edits landing inside 30 minutes

CAPTURE FINDING -- this changes PRD §5, and it is the most important output
of M0 besides the number itself:

  file-history-delta   2110    <- what the thesis assumed was the whole story
  tool_use file_path   5090
  bash-shaped writes   1649

file-history-delta sees under a quarter of real edits.  It is present in only
63 of 197 transcripts.  Most edits arrive as Edit/Write/trueline_edit tool
calls, and a further ~1650 arrive as shell redirects, `sed -i`, `tee` and
heredocs -- which is how Claude Code's auto mode is instructed to edit files.

A reader built on file-history-delta alone would have found 6 collisions and
CANCELLED THE PROJECT.  The same 30 days, read properly, contain 97.

POSTSCRIPT (2026-08-22, after M1 shipped)

This file records the measurement AS TAKEN.  The shipped reader is stricter
than the throwaway script that produced it, so the numbers no longer match
exactly, and both are correct:

  M0 script, 30d          97 collisions
  shipped skein, 30d      ~91 collisions

The shipped reader added two filters M0 did not have:

  - heredoc bodies are stripped before scanning a command for redirects, so
    `a.at > c.at` inside a heredoc no longer invents a file called `c.at`
  - an agent's own store (~/.claude, ~/.codex, opencode storage) is excluded,
    because editing a transcript is not project work

Both remove false positives.  The gate was >= 5.  Nothing about the decision
changes, and the finding that mattered -- that the documented capture path is
under a quarter of real edits -- is unaffected.
